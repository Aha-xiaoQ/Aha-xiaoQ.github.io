# 决策记录 · R04

| 编号 | 决定 | 理由与取舍 |
|---|---|---|
| ADR-001 | 开发日志为跨项目栏目 | 解决单项目页面冒充栏目；只展示真实已登记项目 |
| ADR-002 | 保留“开发日志”和六项主导航 | 同时容纳笔记、过程和协作；“项目”仍负责成品展示 |
| ADR-003 | 共享外壳/主题/转场只有一个来源 | 不让后续项目重新长出独立后台；项目组件只管正文 |
| ADR-004 | 公开阅读与维护分层 | 观众先看到价值和进展；草稿、路径、校验下沉，仍明确维护页非私密 |
| ADR-005 | 兼容旧状态，不迁移或重置 | A/B 及两种 R03 并存过，主动转换会增加丢数据风险；只允许确认的一套 |
| ADR-006 | 数据登记而非复制页面 | 新增项目是 descriptor/state/catalog 变化，通用代码不用项目名判断 |
| ADR-007 | 已发布与本地交付分开 | 不能用版本号或测试数量冒充实际部署成果 |
| ADR-008 | 零第三方 npm 依赖，渐进改造 | 先解决当前协作与结构，不为这次栏目重做整个技术栈 |
| ADR-009 | 脚手架默认 draft | 不把未确认的新项目或占位内容挂给观众 |
| ADR-010 | 本轮不拆游戏引擎 | 先建立真实基线/回归，再小范围等价拆分，避免手感倒退 |

## 被取代的旧 UI 决定

R01 独立协作中心的主题、后台壳被 R02/R03 原生接入取代。本轮进一步取代“开发栏目首页就是混合马里奥概览”和七个主导航的做法。旧任务、原资料和历史测试报告保持原文，用于追溯，不作为当前界面规范。
