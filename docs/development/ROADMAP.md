# 下一步路线与验收门槛

不设未经确认的完成日期；以可检查的阶段交付代替口头“很快完整”。

## M1 · 多项目栏目本地验收（当前）

交付 R04 数据结构、页面、脚手架、验证与安全安装。完成条件：完整原仓库的导航/直达/回退/语言/减少动画/资源加载通过；原任务与游戏入口无退步。责任：维护者本地验收，记录真实提交/Pages 结果。

相关记录：网站项目 SITE-001、SITE-002、SITE-004。本地组件测试通过不自动把这些项目标 done。

## M2 · 用一个新的真实项目验证接入

先确定项目范围和用户可以体验的内容；登记 descriptor/state/docs。完成条件：不修改主 shell/router；两项目的编号、过滤、导出互不污染；没有虚构占位项目。相关记录：SITE-003。

## M3 · 游戏基线与可复现验收

对齐 I/II/III 公开入口和用户最新 HTML。记录角色起步、跳跃、攻击、受伤、死亡、隐藏房间、奖励、返回、拉旗和音频。手柄/触屏/音频必须明确人工验收，不用自动启动通过代替手感。

先复现历史反馈；已修复的不重复修改。对应原记录 BASE-001/ENG-001 或 SRC-001/TEST-001，取决于 A/B 来源。

## M4 · 第一次可回退的游戏模块拆分

优先试做输入动作映射的纯逻辑边界，保持原键位与动作单位。先加黄金样例，再等价拆分；明确按下/保持/释放；物理参数、地图坐标、伤害规则不夹带修改。分 PR 提交，验证后再考虑音频/场景生命周期。

## M5 · 社区协作运行

从一项有范围和验收标准的小任务开始，认领、讨论、PR、自测、维护者审核、发布组成闭环。依据真实贡献逐步安排模块负责人；不默认给陌生人仓库写权限，不让外部 PR 获得发布密钥。

## 本轮已推进而非只有计划

通用数据模型、登记脚手架、项目级路径/页面、构建校验与独立网站任务已经实现。后续游戏等价拆分仍未执行，不能把网站工程工作计入游戏完成度。
