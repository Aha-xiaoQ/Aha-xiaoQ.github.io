## 用户要求与本轮决定

开发栏目必须能容纳后续新项目；混合马里奥只是项目之一。继续沿用主站外壳、原生路由与转场；“开发日志”合并笔记/开发、不增加顶栏项。首页用观众能理解的语言；任务细节、技术路径、导入导出下沉。交付包必须带重要文档，避免对话中断丢信息。

## 已落地

通用项目索引；项目级六种视图和文档详情；项目过滤、任务搜索/状态/分页；数据验证；新项目草稿生成器；直达页面构建；安装冲突检测、备份、回退；跨项目状态隔离；已登记网站本身与混合马里奥两个真实项目。

网站自己的 SITE 任务独立记录。新增项目先是 draft，资料确认后才改 public。测试用第三个项目不进入交付目录的公开索引。

## 不要误读

本轮没有修复游戏手感或拆分引擎，没有承诺 2027 年 5 月做完。没有新的服务器、登录、GitHub 后台写入或实时问题同步。新项目提供 JSON 文件维护与下载，不假称已有多项目网页编辑器。draft/noindex 都不是保密或授权机制。

旧 R03 有两条并行分支；版本号相同不代表可随意叠加。R04 替代单项目首页的 UI 决定，但不覆盖旧任务内容和历史结论。此前要求另一种导航或独立主题的历史说明已被本轮页面规范取代。

## 接续操作

1. 在完整原仓库验收真实导航、图片、字体、CSP、草稿持久化及游戏入口；记录实际结果。
2. 审阅 diff 后由用户推送。把实际 commit 和部署结果写回网站状态，不能由包版本推断。
3. 用真实需求登记下一项目；无需改 shell/router。未确认的项目不要挂空卡片。
4. 对齐三期游戏与用户手中最新版，录制现有行为，再选择一个纯输入映射模块进行等价拆分。

具体范围、验收门槛见 ROADMAP.md。测试已覆盖和未覆盖项以 TEST_REPORT_R04.md 为准。
