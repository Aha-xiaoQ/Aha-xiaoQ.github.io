# 技术架构与修改边界

## 两层而不是两个网站

原站层：`site-shell.js` 负责页眉、主导航、页头、页脚；`site-router.js` 负责 URL/历史/统一过渡与资源准备。

栏目层：`assets/journal/model.mjs` 管数据和项目路径；`render.mjs` 管正文；`runtime.mjs` 管挂载/卸载、读取、筛选和旧工具适配；`journal.css` 只管栏目内部布局。项目名字不进入这些通用模块的条件分支。

原生路由对 notes/dev 区域委托通用项目解析。构建器为公开项目生成真实 HTML 地址，所以直接进入或刷新不依赖用户先从首页点击。路由只有一套；筛选使用 replaceState 保存查询条件，不增加一套浏览器导航。

## 数据来源

项目目录读取注册表，项目详情读取 descriptor。任务由 descriptor.state 指定，状态缓存按 projectId 分开。不同项目可以各自使用 SITE-001 等编号，不会串在同一状态对象里。公开任务是仓库共享快照；不是 GitHub 实时状态，也不是浏览器未提交草稿。

旧 A/B 的适配只做只读标准化，不回写。编辑和草稿导出调用原工具，保留它的 DOM/模型/存储键；进入新项目不会重新初始化或删除旧草稿。维护页是公开网站的一部分，不是安全管理后台。

新项目使用 project-v1 状态。构建前校验归属、编号、日期、依赖、完成依据和链接；draft 不生成公共页面，archived 可保留历史入口。

## 数据与生成物

`content/development/` 是可维护源。`notes/` 的登记页面是生成物。构建器记录 `generated-pages.json` 中的路径和哈希；生成页被手改会停下，不默默抹掉编辑。项目撤回时只移除上一轮由本生成器拥有、且未被编辑的页面。

旧笔记仍来自 `content/site-data.js` 的 `SITE_DATA.notes`。构建在限时 vm 上下文读取站点自身代码；这不是执行不可信外部附件的沙箱。页面只渲染转义后的文本，链接限制为本站绝对路径或 HTTPS。

## 保留/不修改

游戏 play.html、游戏脚本/地图/音效/素材、下载包、版权与许可文件、原任务 JSON、原生成状态与旧交接正文、四份主站共享 CSS 不替换。

外层 HTML 仅修改导航命名、旧开发项和脚本缓存引用。notes 目录首页按新的多项目模板生成；其他原页面正文不替换。已核对的共享 shell/router 增加通用接入，因此不是“只改四个局部文件”。

## 后续游戏重构边界

网站多项目化并不意味着要立即抽象通用游戏引擎。先记录角色/输入/房间/音频行为，再选一个边界拆分；玩法修改与等价重构分开 PR。没有回归依据时，不以框架整洁为由调整物理参数或关卡坐标。

## 自动检查接入

保留原 npm check/test 命令并追加 journal:check / test:journal，所以已有调用这两个命令的 CI 也会检查新栏目。脚本不提升工作流权限。小屏主导航只增加容器自动换行，不增加新菜单或改写共享主题 CSS。
