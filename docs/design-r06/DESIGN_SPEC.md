# 作品组件规范 · R06

## 视觉原则
延续主站红、黑、米白的平面拼贴语言，借鉴 P5R 的高反差、切角与错位层次，但不引入其官方图像、Logo、字体或音乐。主页和页头已获用户认可，不能为内容卡片推翻原框架。

角度只用于装饰底板、图形与标记；长标题、摘要、输入控件保持水平。主要信息先读标题，再读两三行摘要，最后选择动作。不要将每个段落装进一个新的边框，不用闪烁、弹跳或反复播放入场动画补救层级问题。

## 组件及作用域
`assets/workshop-components.css` 仅作用于 `#main .pw-*`，负责项目/游戏/工具条目。`assets/journal/journal.css` 仅作用于 `.journal`。`site-theme.css`、`site-shell.css`、`site-brand-tokens.css`、`site-i18n.css` 仍是原站公共资源，不在本包覆盖范围。

项目卡：类型/编号 → 可视区域 → 标题与摘要 → 标签/明确动作。游戏卡：封面 → 作品说明 → 试玩为主，其余操作从属。工具卡：功能介绍与预览并排，移动端堆叠。开发项目卡：阶段与摘要由真实数据提供，装饰文字不代替状态。

## 交互与无障碍
原始链接和按钮可键盘访问。整卡点击仅用于只有一个主要链接的开发项目卡；不要在整卡链接中嵌套其它按钮。筛选、任务详情不参与全卡点击。支持减少动态效果；使用原站转场而不是第二套路由。320px、390px、768px、1440px 都需无文档横向滚动。不要截掉关键摘要来硬凑卡片高度。

## 直达页面
更新器让原项目/游戏/工具列表在主站脚本初始化时重渲染卡片；原静态正文保留作禁用 JS 时的可读回退。开发页面继续由 `journal:build` 生成直达 HTML。未来可以增加通用列表静态构建，但不能手工维护两套内容。
