# 图片加载优化验收（2026-10-01）

基线：main `bd70c59f0f1b35ca0b8a66bc1665b75bf9691633`；线上 gh-pages `3cceb652f534d4f202504a97ff0e79ba6f385ecc`。

## 已确认的原因

- 首屏/近首屏游戏封面以 1672–1920 像素 PNG/JPEG 直接传输，卡片实际宽约 346/569 CSS 像素。第 3、4 期封面分别为 1,759,106 / 2,006,941 字节。
- 关于页装饰背景 1,812,564 字节；头像 SVG 原文件 1,842,316 字节，线上 gzip 传输约 177 KB。首页同时预加载该 SVG，实际头像却使用 30,582 字节的无损 WebP。
- 项目卡片精灵图 2,575,722 字节、1536×2288；CSS 只播放第一行。
- 主要页面的已观测图片来自本站，没有发现外链图片请求。当前电脑至 GitHub Pages 的网络路径与各地区、运营商的访问路径可能不同。

## 实施

- 游戏卡片使用原生 picture/source 的 640/1280 宽 WebP，quality 94、method 6。原 JPEG/PNG 留在 img.src：不支持 WebP 或派生图失败时使用原图；原图也失败时显示原有双语提示，保留卡片和作品入口。
- 首两张卡片继续 eager，第一张给予 high priority；后续卡片保留浏览器原生 lazy。没有把首屏全部懒加载。
- 首页静态预加载与实际无损 WebP 头像一致，路由器不再预加载未使用的 SVG。关于页复用同一无损头像，装饰背景保留原尺寸并压缩为 WebP。
- Q 咪只无损裁取首行（1536×208），无缩放，RGBA 解码像素与原首行完全相同；8 列、6 帧、1560ms、两次播放保持一致。完整原精灵图及下载包保留。
- 工具预览使用 1280 像素无损 WebP；实验封面使用 1280 像素高质量 WebP，保留原目录安全约束。
- 原始图片、作品实现、下载文件、许可和权限未改变。沿用原有 import-map、内容哈希缓存版本及 .local/publish 发布投影。

## 同条件浏览器测量

本机隔离 Microsoft Edge，实际 `.local/publish` 产物，390×900、DPR 1、CPU 不限速；每次清空浏览器缓存；CDP 模拟下载 1.6 Mbit/s、上传 750 kbit/s、延迟 150ms。每页三轮，表中为中位数。这里的“移动宽度”是桌面浏览器模拟，另外验收了 DPR 2 的响应式选图，并非实机手机测速。

| 页面 | 图片传输字节（前 → 后） | LCP 秒（前 → 后） | 本轮图片请求完成秒（前 → 后） |
| --- | ---: | ---: | ---: |
| `/games/` | 4,177,107 → 292,090 | 28.324 → 6.216 | 28.307 → 8.895 |
| `/about/` | 3,659,980 → 419,628 | 25.224 → 8.968 | 25.214 → 8.948 |

模拟服务器没有 gzip，因此关于页前测包含 SVG 的完整传输字节；线上实测须单独比较。图片字节包含 CDP 记录的请求传输/协议开销，原文件大小与传输大小并不等同。原生 lazy 的预取范围和时序可造成轻微波动。
文件缩小比例不是加载时间提升比例。首页、工具、实验页还受已有字体加载和布局变动影响，不能从图像缩小推断整体 LCP 必然同比改善；本次未修改字体策略。
