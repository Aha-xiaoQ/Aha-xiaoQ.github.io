# 网站架构与维护

[English](README.en.md)

本目录说明网站当前的内容、语言、构建与更新流程。网站继续使用原有静态页面、共享外壳和原生路由；不引入新的界面框架，不更换配色、主导航、卡片布局或转场。已发布试玩与原始实验作品单独保护。

## 日常入口

在包含完整资源的仓库根目录运行：

```sh
npm run platform:plan
npm run platform:verify
```

`platform:plan` 只显示流程，不写文件、不执行命令。`platform:verify` 先生成内容和页面，再执行源码检查、完整原有测试、字体覆盖检查、发布检查和浏览器回归。它不会提交、推送、修改远端设置或自动填写人工验收。

只生成页面可使用 `npm run platform:build`；本地服务仍是 `npm start`。原有 `journal:build`、`site:build`、`npm test` 等命令继续有效。

## 职责与依赖

`config/site-platform.json` 是站点身份、模块职责、生成记录、原始作品保护和检查顺序的配置入口。

| 层次 | 职责 | 主要入口 |
| --- | --- | --- |
| 内容 | 可编辑的作品、项目、实验和英文消息 | `content/` |
| 数据约束 | 项目资料分组、实验身份、路径和原始文件校验 | `assets/platform/contracts.mjs` |
| 语言与字形 | 一个语言状态；原文保护；字形回退和覆盖报告 | `assets/site-i18n.js`、`assets/platform/typography.css` |
| 页面模块 | 项目目录、独立正文、实验展示、搜索和外壳 | `assets/journal/`、`assets/experience/`、`assets/ui/` |
| 构建与发布 | 从同一内容生成直达页面与公开产物，检查资源完整性 | `scripts/journal/`、`scripts/publication/` |
| 交付 | 编排既有构建器、汇总检查、创建差异包 | `scripts/platform/` |

模块表明确职责和依赖关系，并检查循环与重复登记；它不是对全部历史代码实施的 import 沙箱。既有游戏包内部结构没有在这次网站升级中重构。

内容源、生成文件和本地工作资料分开维护。每个生成器仍保留原来的手工编辑保护；不要直接修改生成页面来修正文案。当前生成文件及其归属通过配置中的 `generated` 记录查找。`.local/` 保存构建、检查与发布工作资料，不作为网页内容发布。

## 内容从哪里改

作品和视频入口仍以 `content/site-data.js` 为准；项目介绍、资料和阶段来自 `content/development/projects/<id>.json`。视频同步继续保留 README 中约定的独立视频区，不替换其他正文。

网站项目可用 `startDocuments` 选择概览中的资料入口，用 `documentationGroups` 对资料分组。两者引用已有资料 ID；不存在或重复的 ID 会导致检查失败。调整分组无需修改通用渲染器。归档资料保留原地址，不混在当前主要下载入口中。

新项目继续使用 `npm run journal:add -- ...` 创建草稿，再填写项目文件。公开前明确可用入口、阶段、贡献方式和资料，不把计划或本地验证写成已发布。

## 新增实验

实验登记统一放在 `content/experiments/catalog.json`，每项对应 `content/experiments/<id>.json`。记录保存原始提示词、模型、明确记录的推理强度、作品路径和字节校验值。未记录的推理强度使用 `null`，不推测评分或模型排名。

准备好原始 HTML 和提示词文本后，例如：

```sh
npm run experiment:add -- --id paper-bird --title "纸鸟飞行" --subtitle "观察一次动画生成结果" --model "实际使用的模型" --prompt-file experiments/paper-bird-prompt.txt --artifact experiments/paper-bird.html --dry-run
```

移除 `--dry-run` 才写入登记；默认 `visibility` 为 `draft`。确认内容和许可后将记录改为 `public`，填写适合访客阅读的说明并运行完整检查。目录、资料入口和作品详情由登记生成，无需添加实验 ID 分支到路由或渲染器。修改原始文件时应明确新增版本，不能悄悄让旧记录的 SHA-256 对上新作品。

网页预览只在点击后载入，使用不带同源权限的沙箱。停止或离开页面会清理 iframe、请求及回调；原始下载文件不被翻译脚本改写。

## 英文与原文保护

英文新增和调整写在 `content/locales/en.json`。每条消息使用唯一 ID，并保留中文原文和英文译文。原来的冻结字典保留兼容，不通过多个页面私下维护不同语言状态。

新功能可使用稳定消息 ID：

```js
const label = SITE_I18N.message('status.loading-resource', { name: 'Guide' });
statusElement.textContent = label;
```

参数名在中英文之间必须一致。既有模块可继续使用 `SITE_I18N.translate(sourceText)`；这一兼容接口不会覆盖用户输入。自定义模块应在更新 DOM 后调用共享处理器，而不是增加另一套全页观察器。

`lang` 查询参数、手动选择和本地偏好有明确顺序；切换语言保留搜索条件、锚点及历史视图数据。输入框的 placeholder 和无障碍名称可以翻译，但 value、代码、用户编辑区及标记 `translate="no"` 的原始提示词不会改写。尚无英文的中文叶节点会标注原文语言，不冒充完成翻译。

历史记录和引用原文不自动改写；当前翻译覆盖不等于所有历史文章都有英文版本。对新的重要页面补齐消息后，再检查英文实际显示与搜索结果。

## 字体策略

保留既有霞鹜文楷本地子集和字号。`assets/platform/typography.css` 只统一字体继承、代码等宽字体和后备字体，不重新定义主题几何。已明确的“鹈、鹕”使用固定版本的文楷网页子集补充；已有“尼”的补充保留。后备字体请求失败时仍显示可读系统字体。

```sh
npm run platform:fonts
```

此命令读取仓库中实际 WOFF2 的 cmap，报告已登记项目及新增译文的本地字形覆盖。报告分开列出主要字体缺字、声明的远端补充和需要系统回退的字符。它不修改或下载字体，也不声称已经观察到远端字体成功加载。报告保存在 `.local/platform/font-coverage.json`；这份报告应与浏览器实际显示一起使用。

## 资源与缓存

`assets/platform/import-map.json` 由当前模块内容生成，将已有版本字符串映射到同一份当前代码，避免同一模块因 URL 不同重复初始化。HTML 中的模块入口也同步版本化。公开产物会根据它实际包含的文件重新生成映射；源代码映射不能授权私有工具进入公开目录。最终审计会验证映射结构和实际目标是否存在。

导入映射只管理代码身份，不更改业务路由、页面内容或游戏状态。原始游戏和实验 HTML 不注入站点脚本。

## 验证与结果

配置中的步骤具有依赖关系。独立检查失败后继续收集其他独立检查的结果；依赖失败项的发布及浏览器步骤会标为 blocked，而不是显示通过。汇总记录包含执行结果、命令日志、源码指纹和原始作品校验。

浏览器检查使用独立的临时 Edge/Chrome/Chromium 配置，不读取个人浏览器登录状态。首先验证语言与预览组件，再访问真实发布目录中使用共享外壳的页面，检查中英文、桌面与窄屏、资源错误和前进后退。原始游戏和动画脚本不作为这项网站浏览器检查的执行目标。远端服务与字体在后备场景中刻意不可用，这不等于远端可用性验证。

找不到浏览器时可设置 `XIAOQ_BROWSER` 指向其可执行文件；检查不会静默跳过。企业浏览器策略阻止测试地址时应由设备管理员判断，工具不修改或绕过该策略。

查看 `.local/platform/latest.json` 和其中的每步日志。`ok: true` 表示该次本地流程通过；`approved`、`pushed`、`deployed` 不会因此自动设为真。

## 以后生成一键更新包

在完整仓库修改、完成验证后，指定要更新的远端基线：

```sh
npm run platform:verify
npm run platform:pack -- --base <完整提交SHA> --out ../XiaoQ_Site_Update.zip
```

打包器检查最近成功的验证记录与当前文件指纹一致，仅打包基线以来的作者文件差异；生成文件由目标机器重新构建。运行验证后再改文件，需要重新验证。ZIP 必须输出到仓库外，已存在的文件不会覆盖。

这个流程面向网站代码、内容、资料和新实验；字体文件、游戏包、已有试玩、源码下载档案、工作流与凭据不进入通用网站差异包。游戏等内容继续使用其专门发布流程，而不是放宽此保护。

接收者完整解压到新目录后运行 `START.cmd`，或先用 `CHECK_ONLY.cmd`。两种入口使用同一完整检查流程；后者不提交、不推送。推送器使用独立克隆，复用官方 GitHub CLI 登录，核对目标账号、分支、基线、暂存范围与原始作品；只有检查全部通过才普通推送。远端在过程中出现新提交时停止，不强推，不自动改 Pages 设置，也不自动回滚他人提交。
