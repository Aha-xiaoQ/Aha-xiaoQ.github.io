# 网站字体维护

## 日常更新

在完整仓库运行 `npm run platform:verify`。一键更新器调用同一流程，不需要手动安装字体。
首次建立缺字字库，以及未来文案需要新增字形时，构建程序需要联网取得固定版本资源。成功生成的字形随网站本地托管；普通访客不必依赖第三方字体 CDN。

## 字形的来源与职责

主字体仍为现有的霞鹜文楷 Regular / Medium 子集，不替换已覆盖字形、不调整字号、颜色或间距。
`scripts/platform/font-support.mjs` 收集双语内容、动态运行文案及原生站点页面的字母、汉字、数字和标点。
构建器读取实际字体的 cmap，按缺字选取 `lxgw-wenkai-webfont@1.7.0` 的 Regular / Bold 分片，核对固定 Git 树、CSS 和字体 blob 身份，再验证真实 cmap 覆盖。
生成的 CSS 只声明缺字对应的 unicode-range，同时提供 `LXGW WenKai Local` 与既有 `LXGW WenKai` 家族别名。已覆盖的原始字形保持由原子集绘制。
独立的 Local 别名避免旧远程补充字体与新本地字体同名时，被 FontFaceSet.load 一起加载。原有回退保留在其后，不再作为缺字验证的成功依据。

## 字符采集的边界

JavaScript 由固定版本 Acorn 8.15.0 静态解析，采集字符串和模板片段，不执行被检查的代码。
注释、标识符和正则表达式不属于页面文案；不能先解码整份源码，再把正则的 Unicode 范围端点算成待显示字形。
字符串与 JSON 转义只解码一次，网页实体单独处理。普通数据与对象键仍保守采集；仅对已知的 `SITE_EN` 和 `SITE_LOCALE_MESSAGES.en` 译文映射区分查找键与输出值。
中文页面内容和 `SITE_LOCALE_KEYS` 的中文输出仍参与检查，不能通过“它是翻译源文”来排除真实缺字。
第四期中文标题使用普通拉丁字母 `IV`，对应的稳定消息编号保留；旧 `SITE_EN` 查找别名继续兼容英文翻译。
解析器只在构建工具中使用，源码和 MIT 许可位于 `scripts/platform/vendor/acorn/`，无需额外安装 npm 依赖，也不加入网页运行资源。

这是保守的静态采集，不是完整的数据流或可见性分析。最终浏览器检查继续检查实际 DOM；任何字符真正进入被检查的标题、正文或控件时，缺少字形仍会阻止发布，不设置单字忽略名单。

## 字重匹配

主字库分别注册 400、500、600、700。补字 CSS 必须使用相同的四个精确字重，不得为同一 `LXGW WenKai` 家族混入 `500 700` 范围声明。否则浏览器可能选中不完整的匹配组，使原来已有的汉字和拉丁文字退回系统字体。
生成记录保留 `400` 与 `500 700` 两种资源分组，CSS 输出将后者展开为 500、600、700；同一字体文件可被多个精确字重引用，不重复下载或改写字库。

## 构建顺序

统一流程在页面构建前准备字形，再在页面生成完成后复查新文字。源码检查 `platform:check` 和独立 `font-coverage` 均检查实际覆盖，不会把缺少汉字的结果当作系统回退放行。
发布浏览器检查还收集实际 DOM 中解码后的文字及输入提示，和本地字库比较；这可以发现静态抽取遗漏的实体或动态文本。
`font-render-regression` 用运行时生成的原创几何测试字形，检查主字库与补字的匹配行为。旧范围声明作为诊断记录，修复版、资源缺失和元素字体被覆盖的反例作为必需检查；不要求未来浏览器继续保留旧匹配问题。
`font-source-pages` 检查主分支中实际生成的页面，覆盖中英文与 1440、390、320 宽度。通过浏览器读取页面已有标题、正文、按钮等元素的直接 Text 节点所使用的字体，不插入测试段落或强制改变它们的字体；另用已登记的正文字符检查主字库和补字混排。
发布产物的浏览器检查也执行同一项实际元素检查。中文或拉丁正文回退、无法取得字体选用证据、资源加载失败均会阻止推送。代码块和原创游戏不在这项站点字体检查的范围中。

## 页面文字归属与展开状态

实际字体检查以原有 DOM Text 节点为单位。正文段落包含 `code`、`kbd` 或其他子元素时，不把后代元素的等宽字体统计到正文上；也不会为了通过检查把代码强制改成正文用字。每段普通文字自身退回系统字体时仍然失败。

`details` 收起时，内容可能保留布局矩形却没有绘制字形。检查先核验当前可见文字，再通过原生 `open` 状态展开内容核验。嵌套折叠及带 `name` 的互斥分组均单独处理，最终恢复原来的 `open` 属性、分组和滚动位置，不把未绘制内容判成缺字，也不把折叠正文永久排除。恢复失败及字体查询失败同样阻止推送。

混排字符检查使用 `"LXGW WenKai Local", "LXGW WenKai"`，同时包含补字库与主字库；不能用只有补字的家族证明正文主字库的覆盖。四个字重分别检查，缺少任一部分仍然失败。

实验室播放区的小标签与作品链接的文字元信息继承页面字体。装饰图形的字样、原版游戏与代码展示保持各自的职责，不用全局 `!important` 替换所有元素。

页面就绪以同一个站点文档、已解析的 DOM、正确语言、已挂载内容及当前适用的本地样式为依据，字体检查不等待无关图片或影片全部下载。请求失败、页面错误状态或就绪超时会记录实际 URL、语言和未完成样式；不是把超时当作通过。

`font-render-regression` 还运行 `scripts/platform/browser/font-ownership-regression.mjs`：覆盖实际标签规则、带代码的正文、嵌套文字、展开/收起状态、互斥分组、缺少字库以及查询失败。它使用程序生成的几何字形检查机制；真实站点字体仍须通过随后的源页面及发布产物检查。

## 文件与缓存

- `docs/platform/font-provider.json`：固定版本上游目录与 CSS 数据；首次生成后复用。
- `docs/platform/generated-fonts.json`：本地产物身份、字形与生成所有权。
- `assets/platform/font-support.css`：自动生成的缺字范围与本地引用。
- `assets/platform/font-support/<SHA-256>.woff2`：内容寻址的字体文件。
- `.local/platform/font-coverage.json`：本次完整诊断，仅供本地维护。

不要手工修改生成记录或字体文件；冲突会停止构建。原始站点子集也不能被构建器悄悄替换。
网站增量包仍不携带字体文件。接收端构建后，只允许暂存经过本地字节校验、已登记且内容寻址的字体产物；普通载荷不能借此夹带任意字体或二进制文件。
字库文件名随内容变化，页面中的 `data-platform-font-support` 样式链接也使用 CSS 内容摘要，不再依赖固定版本的嵌套导入。字体发生变化时，`font-finalize.mjs` 通过既有页面构建器更新链接及其所有权记录；重复构建必须收敛，不手工覆盖生成页面。
`.local/platform/font-pages.json` 记录源分支页面中失败元素的位置、文字、字重和实际字体；`.local/platform/font-regression.json` 记录字重匹配对照。不得通过关闭缓存核验或跳过字体检查解决冲突。

## 许可证副本

字体构建从 `assets/fonts/LXGWWenKai-OFL.txt` 读取既有许可证，原文件字节保持不变。
仅对生成的 `assets/platform/font-support/OFL.txt` 统一 LF 换行，去掉行尾 ASCII 空格和制表符，并保留一个末尾换行；不改动版权人、许可条款、段落顺序、标点或正文内空格。
生成记录分别保存原始许可证与发布副本的 SHA-256、字节数和格式化规则。字体检查会同时核对副本内容及来源记录，而不是只检查文件是否存在。
旧版生成记录在重建前仍按原摘要验证，确认无人修改后才更新副本及记录；手工编辑或缺失的生成文件仍会阻止构建。
再次构建不会重新引入原文行尾空格。提交前的 Git 空白检查继续对所有暂存文件执行，不对许可证或其他文本设置豁免。

## 验证范围

字符覆盖不等于字形在所有系统上的审美认证。Emoji、数学符号和其他非文字符号单独记录，保留系统回退；不承诺覆盖全部 Unicode。
独立游戏、影片画面和不使用站点语言模块的原创 HTML 不自动改写。中秋重新绘制程序有自己的字体检查；最终 MP4 的字幕已烧录，播放不需要字体。
自动检查与原有全量源码、发布和浏览器检查一起运行，不替代真实设备观感复核。

## 独立页面的就绪条件

`#app` 是路由外壳的实现细节，不是字体检查的页面契约。直接在 `body` 下提供 `main` 与 `h1` 的独立页面也要进入完整检查；不能为个别路径设置跳过列表，也不要为了检查给页面额外套容器。

`scripts/platform/browser/font-page-ready.mjs` 仍要求目标文档、已解析 DOM、正确语言、正文主区、标题和本地样式就绪；开发页还须挂载 journal。`app` 字段只用于诊断，不决定通过。真正缺少正文或标题、语言不对、样式未完成及资源错误仍会阻止检查继续。

`font-render-regression` 额外使用当前 Q咪页面的主区源码，对直接主区、路由容器和其他容器结构执行浏览器回归；独立页面通过就绪判断后，仍须取得原文字节点的实际字体证据。该回归中的地址和语言状态是受控输入，测试字形是程序生成的几何字形；不是在线页面或真实 WenKai 视觉验收。生产源页面及发布产物仍按原流程逐页检查，不改变页面数量和失败门槛。
