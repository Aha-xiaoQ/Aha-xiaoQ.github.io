# 网站内容更新流程

触发：用户说“更新网站”、补充一部作品、提供 BV 号或要求修正公开状态。维护者负责完成关联入口与实际产物验证，不只交付单页。

1. **确认基线与范围。** 查看工作区和远端；获取最新远端并核对差异。干净且可快进时更新模板；已有未发布改动时保留并整合，不能覆盖。继承本次授权：本地预览仍只做本地预览，不因本流程自动推送。
2. **核实作品身份。** 对照用户确认的作品、封面、链接、日期和实际发布状态。视频平台可用、网站本地生成、网站部署成功分别记录。视频发布文案明确平台，不把收录日期当视频发布日期。
3. **同步关联内容。** 作品登记是正文源；同步 `content/site-data.js` 的 `profile.now`、所属项目的 `updatedAt`、`links`、`updates` 及必要状态。使用 `sourceId` 绑定首页作品，避免发布投影退回旧游戏。首页“重点入口”与该引用共用目标和栏目名称，不能固定指向项目总目录。新增更新写入所属项目，全站更新由生成器汇总。不要为更新时间而改变无关任务状态或删除历史记录。
4. **同步语言与入口。** 补齐英文；核对目录、详情、项目/全站更新、首页当前状态、搜索及适用下载链接。视频作品应同时核对用户提供的 HTML 与源码包；已有文件需接入 resources 并验证下载哈希，不得只放 BV 链接。说明交互主片与剪辑成片的实际差别。生成页面不得手改。
5. **构建并检查。** 按仓库原有构建链运行 `journal:build`、`site:build`，补齐字体；运行 `site:status:check`、`check`、相关回归、`release:test`、`release:prepare`、`release:check`。完整测试若遇已有失败，应记录实际失败及是否与改动有关，不能宣称全绿。
6. **验收实际产物。** 在 `.local/publish` 的服务器打开首页、`/notes/updates/`、所属项目更新、作品目录和详情。检查新标题、日期、状态、BV、封面、字体、双语与手机显示。测试源码数据正确不足以证明发布投影正确。保存简洁截图/检查结果；独立复核本次改动及曾漏项。
7. **交付或发布。** 本地任务给出仍可打开的预览；已明确授权发布时才执行既有发布流程并检查线上对应页面。说明完成阶段和实质性未解决问题。

## 状态绑定检查

`npm run site:status:check` 对比首页作品引用、标题与日期、公开投影、实验室关联入口和更新记录，并检查是否有日期更新的公开作品未反映在“最近作品”中。历史无引用的纯游戏首页仍兼容；新增作品应填写 `sourceId`。同日多部作品的排序由维护者确认，不推断用户偏好。

回归必须覆盖：已登记视频却漏更新记录、首页日期或标题仍旧、首页引用草稿/不存在作品、发布投影把视频换回游戏，以及原有无引用游戏页兼容。
