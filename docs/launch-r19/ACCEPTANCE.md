# 发布前验收（须在完整站点执行）

本清单所有人工项默认未通过。测试目录缺媒体时不得用假资源消除告警。

## 自动检查

```sh
npm run launch:check
npm run test:launch
npm run experience:check
npm run journal:build
npm run site:build
npm run release:preflight
npm run check
npm test
npm run launch:audit
```

`launch:audit`输出文件指纹及缺失引用。核对全部错误和大图警告；完整素材、所有深链和已下载源码必须真实存在。审计只扫描登记页面和直接HTML本地引用，外网、CSS嵌套、动态模块与运行时游戏素材需浏览器检查。

## 七项人工记录

复制REVIEW.template.json到仓库`.local/launch-review.json`，填写当前audit指纹。

1. 桌面浏览器：真实HTTP，首页→游戏→介绍→试玩→返回；前进后退、刷新、复制、深链接。
2. 手机/触屏：常用真实设备，搜索、说明、横屏/竖屏。游戏若不支持触屏必须如实说明。
3. 键盘/读屏：Tab顺序、焦点恢复、按钮可达名称、无焦点陷阱，至少一款读屏软件。
4. 慢网/恢复：限速、阻断图片、下载失败、搜索索引失败后重试；不清空用户存档。
5. 游戏自然流程：无诊断接口完成首个目标，进入地下、奖励、死亡/暂停/恢复，核对手柄、声音。
6. 下载与版本：从真正网页下载ZIP、解压构建，核对当前0.4.2来源。候选与公开试玩分别标识。
7. 内容和权利：三个主要资料入口、未验收状态、素材说明、作者署名，不擅自扩大许可。

每项填入passed、审阅人、日期、可核对证据。然后运行：

```sh
node scripts/launch/check.mjs --gate --evidence .local/launch-review.json
```

此命令检查证据完整及指纹一致，不核验证据真假、不代替维护者判断、不进行部署。只补了一部分时保持pending，不为让命令变绿而编造记录。

## 首次访客观察（建议，不是已实施研究）

邀请未参与开发的人不看聊天记录完成“找到一款作品、开始、查看帮助、返回、找到源码”。记录卡住的位置，先修阻碍任务的问题，再考虑装饰。没有实测就不发布用时、满意率或转化率。
