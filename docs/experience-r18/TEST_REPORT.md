## 检查中修正的问题

1. 静态增强函数曾从首个header跨过边界匹配到正文目录，导致重复搜索入口。已限制为第一个header内部替换并加入幂等检查。
2. 原始搜索按钮在部分布局被挤窄。已加独立最小宽度、不换行和明确flex约束，四档宽度重测。
3. 原生路由的动态搜索模块URL若沿用路由缓存号，会与HTML模块标签的URL不同，浏览器可能重复执行。已统一为同一`experience-r18` URL，并增加契约用例；真实浏览器网络链路仍待实机。
4. 安装器“转为草稿后不再索引”的初稿用例误写`url`而实际契约是`href`，已修正并复跑24项，不跳过失败用例。
5. 新缓存版本只调整三项历史测试中的资源查询号预期；原目标、限制与安全断言保留。
6. 一次浏览器组合重跑超过工具时间上限，没有将该批次计为成功；随后单独执行全部35项并取得结束记录。

## 最终ZIP复核方法

最终压缩后另行解压，CRC及SHA清单核对、重跑24项安装器；从新R17副本安装，运行270项网站回归与三类构建一致性，核对受保护字节、重复应用和回退。最终ZIP自身SHA与实际运行结果单独写入包旁`FinalVerification.json`，避免自引用哈希。包内validation保存打包前真实日志。

复跑：仓库`npm run test:experience`、`npm run experience:check`以及原完整根检查；更新包`node --test tests/update.test.mjs`。根package中的历史服务/游戏任务在文本夹具中不完整，不能用替身声称完整`npm test`已经在用户站点通过。
