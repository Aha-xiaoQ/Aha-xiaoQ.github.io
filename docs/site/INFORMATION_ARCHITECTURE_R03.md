# R03 · 页面结构与阅读层级

## 这轮采用的原则

保持 R02 已接入的主站样式、导航、页头页脚和原生转场，不另建后台，不增加一级菜单。详细页面使用真实 HTML 路径并进入现有 `site-router.js`，不是另建路由器或 iframe。

项目首页只回答三个问题：这是什么、当前重点是什么、我从哪里参与。源文件路径、基线 SHA、全部任务、完整决策、导入导出不再全部堆在首页。

## 页面地图

| 路径 | 用途 | 阅读上限与展开方式 |
|---|---|---|
| `/dev/index.html` | 项目概览 | 当前重点一项、任务数量摘要、三个入口、试玩引导 |
| `/dev/tasks/index.html` | 任务看板 | 每页最多 8 项；搜索、状态与模块筛选；详情弹窗或折叠展开 |
| `/dev/docs/index.html` | 开发文档 | 启动、结构、参考三组入口；保留原有三期路径 |
| `/dev/docs/architecture/index.html` | 结构与模块 | 现状与目标分开；路径/计划不冒充实现 |
| `/dev/docs/reference/index.html` | 前辈参考 | SMBC 参考范围与许可边界；不自动取得上游素材 |
| `/dev/updates/index.html` | 更新记录 | 页面修订与任务历史分开；完整决策按需展开 |
| `/dev/contribute/index.html` | 参与指南 | 测试、认领、代码/文档三类入口；完整操作折叠 |
| `/dev/manage/index.html` | 交接与同步 | 负责人/维护者的导入、导出、续接及发布记录 |

`/dev/`、`/dev/mario-mix/`、`/dev/mario-mix/index.html` 仍可进入概览；`/dev/guide.html` 是参与指南的旧入口。旧的 `#board`、`#tasks`、`#handoff` 等锚点保留兼容显示。新的内部链接应使用上表路径，不再新增长页面锚点导航。

## 视觉约束

主站的 `site-brand-tokens.css`、`site-shell.css`、`site-theme.css`、`site-i18n.css` 是公共样式来源，本轮不改写它们。组件沿用 `.entry`、`.button`、`.section-head`、`.tag`；`site-development.css` 只在 `.mm-dev` 内细化栅格、留白、表单、分页与任务布局。不得另定义全局配色、字体或页头。

每个分页面都复用同一主导航、页头与页脚；页内导航最多五个：概览、任务、文档、更新、参与。维护操作放在低优先级的“交接与同步”入口中。任务数量不是整个游戏的完成百分比，不显示无法证明的发布进度。

转场沿用主站实现；本轮没有新的闪屏、入场动效或卡片动画。设备要求减少动态时继续服从主站设置。

## 内容和状态

A 版共享源仍为 `collab/project.json`；B 版仍为 `docs/mario-mix/project-state.json`。组件通过原模型读写草稿，不改 schema、不搬迁 localStorage 键，也不清空记录。

`dev/workspace.html` 是原任务组件与运行清单的内部来源，`dev/guide-source.html` 是原指南来源。它们不是新的后台或第二份共享状态；页面无网络写入能力。保留完整组件节点是为了不丢失已绑定的编辑、过滤和草稿逻辑；只有当前视图对访客与辅助技术可见。

浏览器第一次进入开发栏目读取一次状态；同一会话跨子页复用节点与内存。重新打开页面才读取最新发布的共享快照。状态数据请求增加一次性的缓存参数，避免旧缓存遮蔽新记录。

## 后续编辑顺序

先读 AGENTS、R03 交接与原状态，再改一个明确范围。增加大量内容前先判断是否应该进分页面。新增页面必须同时增加真实 HTML、原生路由、视图映射与测试。界面修订的记录写入 docs/site，不为了美化而把游戏任务标为完成。
