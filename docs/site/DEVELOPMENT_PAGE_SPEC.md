# 主站开发栏目规范（R02）

日期：2026-09-15。来源：维护者明确要求——开发已是主站导航项，进入后不得像切换到另一个站点。

## 不可回退的边界

开发是主站 `content` 类型页面，复用 `assets/site-shell.js` 的 header、page-head、footer，以及 `assets/site-router.js` 的前进、后退和转场。不是独立仪表盘，不是 iframe，也不新增一个前端路由器。

原 `assets/site-brand-tokens.css`、`assets/site-shell.css`、其导入的 `assets/site-theme.css`、`assets/site-i18n.css` 为视觉来源。R02 不改写这些文件，不复制其中的全局颜色、字体、导航或页面宽度到开发页。以后主站改主题，开发页随共享资源变化。

新 CSS 仅允许 `.mm-dev` 下的业务组件布局，以及已增加开发项的导航容器换行。不得定义自己的 `:root`、`html`、`body`、全局 `main`、`.brand`、`.page-head`、`.site-header`、`.site-footer` 或另一套 `.button` 主题。

原生页头只保留一份 Q 标识和一组全站导航。栏目内部目录是正文中的次级导航，不再使用固定侧边栏，也不重建第二个工具栏。旧 R01 的大标题、版本印章、独立页脚和自制 Q 字符标志已移出外层框架。

`/dev/`、`/dev/index.html`、`/dev/mario-mix/`、`/dev/mario-mix/index.html` 都是同一开发栏目入口；`/dev/guide.html` 为同一框架内的参与指南。主导航只出现一个“开发”。文档 Markdown 是源码文档链接，不是额外后台。

## 功能与状态

两个历史 R01 包拥有不同状态格式。安装器必须检测实际使用的一种，不能自动把一种格式的任务覆盖到另一种。发现两种状态同时存在时，停止并逐项核对。

A 版状态源：`collab/project.json`；B 版状态源：`docs/mario-mix/project-state.json`。R02 不修改两者，不清除或迁移浏览器存储键，不假装已推送。页面修订 R02 与任务记录中 R01 的历史交付版本分开。

离开开发栏目时保留组件节点与内存状态，暂停观察器；重新进入时复用组件而不是重复执行脚本、重复绑定事件。已保存草稿、搜索条件与任务展开状态不因栏目切换丢失。浏览器未允许持久存储时，仍应立即导出草稿后再关闭窗口。

语言按钮由原站管理。全站导航、标题与语言选择沿用主站；任务记录与编辑内容保留原始中文，不自动翻译或改写用户数据。

## 发布者验收

- 首页、笔记、游戏、开发之间来回切换；header、footer、导航位置和主题一致，无全屏空白、无第二套侧边栏。
- 从地址栏直达开发页，再刷新、后退、前进；“开发”高亮正确，导航不重复。
- 320、390、768、1440 像素宽度没有横向溢出，七个导航项仍可操作；测试英文主导航换行。
- 保存任务草稿，切到其他栏目再返回；搜索、展开状态及已保存记录仍在。刷新后核实本机存储和导出。
- 所有旧游戏入口、下载、品牌资源、原站正文和许可证保持不变。
- `npm run test:site` 通过后仍需原站 HTTP/上线实测。静态断言不能代替转场、字体或游戏验收。
