# 游戏规则与回归验收清单

这是从用户反馈整理的验收目标，不代表当前 main 全部存在这些问题，也不代表本轮修复过游戏。先复现并记录真实版本。

## 不可在结构重构中偷偷改变

保留经典关卡骨架；针对角色的变化单独设计。横版角色和俯视坦克不强行统一物理模型。角色的受击规则、武器、动画和声音保持各自设计。已有试玩/下载入口继续工作。

## 第三期重点

| 模块 | 验收目标 | 本轮结论 |
|---|---|---|
| 手柄放置 | 平地默认位置为角色面前、脚边一格；不是头顶；越界/占用有反馈 | 未运行游戏验证 |
| 改键 | 可保存与恢复默认；键位冲突、手柄断连、死区有定义 | 未运行游戏验证 |
| 宝箱 | 碰触开箱，仅一次；非空奖励落地；拾取显示名称与效果 | 未运行游戏验证 |
| 武器替换 | 旧武器落地可换回；不会原地无限自动换枪；掉落位置有效 | 未运行游戏验证 |
| 坐骑 | 得到奖励即骑乘；握持点、脚底锚点与姿势正确 | 未运行游戏验证 |
| 生态怪物 | 不同地形有对应敌人池和强度；不全部替换成同类史莱姆 | 未运行游戏验证 |
| Boss | 雪原 Boss 位置和出场流程按确认方案；单列设计与复现记录 | 未运行游戏验证 |
| 绘制层级 | 树干、叶片、角色、武器与前景遮挡正确 | 未运行游戏验证 |

## 三期共同检查

分别记录启动、选人、移动、跳跃/俯视移动、武器/能力、暂停、重开、死亡、隐藏关进出、奖励、拉旗和结算。检查音频是否残留旧曲或叠加多首主 BGM。

每条记录带上：文件路径/构建编号、角色与关卡、浏览器/系统、输入设备、步骤、预期、实际结果、录屏或截图、是否可重复。至少一次完整通关和实体手柄测试仍需人工执行；自动测试不能替代“手感合格”的判断。

## 自动化路线（尚未完成）

建立独立开发测试房间：直达场景、生成敌人与物品、查看碰撞框与输入状态、固定随机种子。先选小范围模型测试，再引入游戏流程自动化；不要把本轮协作工具测试报告写成这些功能已经存在。
