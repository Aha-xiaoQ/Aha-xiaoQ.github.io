# 架构与构建约定

## 本次解决什么

已发布 R43 是单 HTML，混合页面、逻辑、图片与音频。本次只进行可逆的源码提取：6 组样式、4 组数据/配置、26 个运行时代码片段、260 个去重素材，以及保留原 script/style 标签顺序的页面壳。

构建链：`src/app/shell.template.html` → 递归展开 `@@E04:file:...@@` → 根据素材清单展开 `uri` 或 `base64` → `dist/play.html`。使用 Node.js 内置模块，没有依赖安装或远端编译步骤。占位符的路径必须在 manifest 中登记。

源片段文件结尾不保留额外空行。原 HTML 中片段之间的空行放在父模板相应 `@@E04:file:...@@` 标记之后，构建时按原顺序还原。不要直接删除父模板中的这些分隔换行，否则固定 R43 字节校验会失败。这一排布同时满足 Git 提交前的空白检查与原 HTML 的逐字节还原。

原文件的一些片段共享未闭合的外层函数作用域，历史覆写函数也依赖注册顺序。它们被保留为编译片段，而非伪装成独立模块；完整语法校验在拼接后进行。不要逐个运行或逐个 import `.part.js`。

## 维护边界

游戏地图数据仍在相应章节代码片段中，没有借整理源码之名修改位置、角色参数或碰撞。标题、CSP、菜单布局、存档键、原始权利声明和资源请求策略保持原值。R43 内置录音保存为独立 MP3，但构建时还原为原 base64 字节。

`manifest.baseline` 固定指向原发布 HTML。检查素材长度及 SHA-256，再用输出长度、整体 SHA-256 和语法校验识别损坏或编译错误。不把单元测试数量当作真实游戏通关次数。

## 与网站和其他工程的关系

本工程位于 `packages/mario-mix-episode4/`；在线试玩仍在 `games/mario-mix-4/play.html`，不自动发布 dist。第三期 `packages/mario-mix-terra/` 与地图工坊 `packages/mario-mix-worlds/` 继续保持原身份。

未来要做真正的模块化迁移，应先将共享状态和生命周期契约提取，再逐项对照原版的输入、存档、碰撞及音频。此次并未建立可替换 M07 的通用引擎或完成 WorldKit 角色接入。
