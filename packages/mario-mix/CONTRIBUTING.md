# 贡献混合马里奥

先完成一项清楚、可验证的小修改。当前最成熟的代码入口是 packages/mario-mix 的输入试点；不是让所有人同时修改三份大型 HTML。

## 一次小 PR

1. 在 [首批任务](docs/WORK_ITEMS.md) 选一项，在仓库 Issue 里写明任务编号、计划文件、验收方式，等维护者确认范围再做大改。文档错字或小测试可以直接提交。
2. Fork 原仓库，在自己的分支开发。普通贡献者无需获得维护者仓库写权限。
3. 运行 game:check、game:test、game:audit，确认修改所在的游戏版本；game:build 得到候选 SHA-256。
4. 对照原始与候选试玩。写清未测试的设备、关卡和音频，不用自动测试冒充通关。
5. 提交 PR：关联 Issue、改动说明、测试证据、风险与回退。小 PR 不顺带格式化所有旧代码。
6. 维护者复查和试玩；通过后再合并。合并与发布分开，网页暂未验证时不覆盖稳定版。

命令示例（你手动运行，不由更新器自动执行）：

```sh
git switch -c test/bill-descent-boundary
npm run game:test
npm run game:build
git diff --stat
git status --short
```

## 首次贡献建议

优先补一个缺失的验收场景、明确一条运行说明、补充一个平台边界测试。涉及运动单位、跳跃参数、伤害、音乐或新素材，先独立讨论，不混进结构整理。
不要更改 golden fixture、baseline.json 去绕过失败；确需迁移基线时，单独 PR 附旧/新来源、差异和回归证据。

## 合并清单

- 修改的是有效源码，不是旧的未加载片段或 .local 构建物。
- 测试可复现；候选哈希与提交源码对应。
- 输入与玩家对象不在纯函数里被修改；原状态副作用留在桥接处。
- 没有 token、本机绝对路径、私密聊天、未知二进制或无证据的素材。
- AI 可辅助，但提交者要能解释关键逻辑、审查依赖与测试结果。

PR 模板位于 `.github/PULL_REQUEST_TEMPLATE/mario-mix.md`；可在建立 PR 时选择该模板。任务表只是本地待办，不代表已经自动在 GitHub 建立 Issue 或有人认领。
