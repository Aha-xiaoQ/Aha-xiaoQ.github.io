# 第三期 0.4.1 架构

## 模块与职责

`src/content` 保存数据与定义，`src/input` 负责动作，`src/simulation` 负责规则，`src/runtime` 负责时序与会话，`src/ui` 只负责显示和交互。构建器将27个实际模块与33个 compat 片段组合为可运行候选；规则、内容和输入模型不依赖 DOM；UI模块通过注入的 document/context 管理界面，宿主通过6个桥接文件提供设备和旧游戏状态。

## 规则与场景边界

物品说明由 `createItemDefinitions()` 提供，每次运行独立创建。后续两个旧武器注册仍会补入同一实例，保留这些已有武器。

`createLootRules({getItem})` 是纯规则端口：`weapon()` 产生装备替换和战斗状态重置；`chest()` 产生一次性箱子认领及散落计划；`notice()` 产生拾取说明。它们不修改传入对象、不播放声音、不存档。桥接按原顺序提交；物理掉落的吸附、碰撞、重拾保护仍属于 compat。

`createStageSession` 明确实例所有者。开始失败/暂停失败/恢复失败会清理该实例；退出先使代次失效，再执行销毁。旧实例不能向新实例发事件，驱动事件只能是 sound/room/complete，不能伪造 generation/type。view 返回独立数据快照。

## 关卡驱动与兼容范围

`legacy-terra-v1` 是原第三期固定入口；它并不消费任意关卡数据。因此会拒绝自定义 legacy 地图/角色/音频组合，且锁定用于展示的底图快照。增加地图使用 `platform-v1`；其运动器、几何画面是独立原型，不等价于泰拉角色。

地图、角色和适配层配置经校验后才能构建；不允许使用未登记音效键。未知能力应明确失败，不能静默降级成错误场景。已有27个模块的所有导出、依赖、测试和桥接入口见 [生成模块地图](generated/MODULES.md)。

## 当前范围

不切换引擎；不新增城堡/原图全套；不改变旧物理和音效时序。暂不把背包、坐骑、武器全部迁成跨地图 actor。`platform-v1` 仍为0.1实验协议，不承诺二进制插件兼容；接口变更需ADR+对照测试。

构建安全使用 lstat 校验目录项，拒绝悬空链接。它不是与恶意本地并发进程对抗的沙箱。新玩家内容通过源码审阅，不动态执行远程插件。

候选附加adventure.css；原模板和console.css保持底稿可重建。HUD/提示绘制接收只读模型，显示偏好独立存储；新控件经过原最早输入路由，不新增包装链。参见 [UI契约](UI_CONTRACT.md) 和 [M05交接](HANDOFF_M05.md)。
