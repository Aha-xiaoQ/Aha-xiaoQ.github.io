# M01 架构现状

## 运行链路

```
内容/资源登记 ──→ 构建器 ──→ media bank（旧加载器适配）
独立 ES 模块 ──→ 显式桥接 ──→ 兼容运行时 ──→ 现有画面和音频
       └────→ Node 对照测试          └────→ 原测试钩子/浏览器回放
```

开发网页使用真正的 ESM import；单 HTML 输出将同一批 import-free 函数模块打包到独立作用域。导出在 build.config.json 显式登记，新增 export 或 import 必须同步构建规则，不静默丢代码。这个小打包器只满足当前的八个简单模块；当模块依赖扩大，优先评估成熟 bundler，不继续造一个全功能编译器。

## 已解耦

Boss、平台建造、地图解码、默认动作、早期逻辑输入、摇杆数学、按键名称、固定时钟。工厂给每个运行时独立实例。旧战斗装配仍会包装 Boss 实例的 damageEye，因此不能在多个游戏实例之间共用同一个可变 API 对象。

## 保留的兼容区

src/compat/ 文件是**编译片段**，共享外层状态和初始化顺序，不能直接 import 单个文件。早期忍者、坦克和历史体素分支是第三期底稿内的既有依赖，暂不移除，也不意味着本轮支持或开发这些分支。源码地图说明各段负责什么。

资源读取、后期输入所有权、技能/道具装配、场景返回、HUD、绑定对话框和缓存仍有全局依赖。此处是迁移债务，不能宣称统一 SceneManager 已完成。

## 参考与候选

参考由同一份兼容源码 + tests/golden 原片段 + 原资源重建。未修改工程可逐字节重建上传 HTML。纯模块变化不影响 golden；修改兼容源码会改变参考，此时 verify:baseline/参考服务拒绝将其视为原版。若继续迁移这些片段，应保留原始上传包用于独立对照，不能自动改 baseline.json 来掩盖差异。

## 新功能依赖方向

独立玩法模块只接收状态、参数和命令，输出结果与事件；渲染/UI 在边缘读取。输入只产生动作，不在每个系统新装 DOM 监听。场景生命周期是下一阶段的重点，不先引入通用 ECS 或万能插件框架。

工程与作品网站隔离：网站只介绍、展示和下载；源码包与候选游戏单独启动。
