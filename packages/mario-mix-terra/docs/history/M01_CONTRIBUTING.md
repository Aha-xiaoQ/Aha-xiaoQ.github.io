# 完成第一个贡献

先阅读 START_HERE.md，在未修改状态运行 build、check、test。选择 docs/TASKS.json 中一项范围明确的任务；先说明改动理由、影响模块和验收方式，再创建分支。

## 一个实际可改的例子

按键显示工作由 src/ui/key-label.mjs 负责。修改显示逻辑，给 tests/modules.test.mjs 增加对应输入用例，再 build。打开候选的按键设置确认名称；游戏移动不应变化。不要修改 dist 中编译后的文本，也不要在旧 compat 文件里新增同名包装。

## 提交前

```sh
npm run check
npm test
npm run build
node scripts/build.mjs --check
```

提交 src、content、tests、docs 及必要的媒体登记。不提交 dist、.local、node_modules、个人存档或整个更新 ZIP。源码的媒体校验值跟随真实文件改变；更换第三方素材必须附来源与许可依据。

## 改动类别

**等价迁移**：行为对照必须一致。**功能/平衡改动**：先确认设计、单独提交、解释预期差异并更新相关测试；不要为了通过测试擅自修改原始底稿的 SHA。**资源替换**：不动物理尺寸与锚点，先列明影响。**UI 改动**：不能同时改输入判定或吞掉游戏按键。

独立模块不得直接读 DOM、localStorage 或某个第三方引擎对象。UI 标签模块只负责显示；设备捕获、菜单焦点和存档尚未迁出时，先通过兼容层明确依赖，不新建第二套全局监听。

## PR 说明至少包括

目标任务、修改文件、验证命令、原版/候选差异、截图或短复现，以及哪些设备/网络环境没有验证。允许 AI 辅助，但提交者应理解代码并完成自测。大规模格式化、换引擎、城堡关或新素材导入不与小修复混在一个 PR。

公共源码与资产授权并非同一件事。所有素材复用仍需逐项核验。维护者合并与发布，网友不需要主分支写权限。
