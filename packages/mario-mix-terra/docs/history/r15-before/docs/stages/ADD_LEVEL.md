# 外部开发者：添加一关

## 十分钟跑通结构（不是十分钟复刻原关）

```sh
npm run verify
npm run stage:new -- --id world-1-4 --title "1-4 开发草稿"
npm run stage:new -- --id world-1-4 --title "1-4 开发草稿" --apply
npm run stage:check
npm run dev
```

打开4193/play.html → 关卡开发 → 勾选显示开发草稿 → 选择新ID → 进入。
脚手架只增加3个JSON：main地图、bonus地图、stage清单，自动发现，无需修改主循环、Canvas、宿主或模块注册。**这些几何来自原创lab样例，绝不等于真实1-4。**

## 正式制作顺序

先选择授权与来源明确的参考，记录游戏版本、关卡、图片/数据来源、访问日期。分开转录地形、对象、机关与装饰。保留底图，角色额外平台写入overlay，不能覆盖基准。地图地形相同，不代表火焰棒速度、隐藏块、触发条件、敌人行为和摄像机边界相同。

声明使用哪个驱动和角色、需要哪些能力。现有原型支持的机制直接编辑JSON；不支持的机制先提设计和测试，写复用模块经维护者接入。不建议为了通过schema删掉尚未实现的原版机关。

验收：两种支持角色都能完成→死后/检查点→bonus往返→拾取不重复→暂停/返回→声音停止/切换→重新进入→输入与UI无串扰。提交候选SHA、录屏和未验证清单。需要跨关背包/物品/剧情时，先等待事务协议，不使用任意全局变量传递。

## 1-4 仍缺什么

本轮没制成原版1-4基础包，未完成旋转火焰棒/城堡Boss/桥与斧头终点规则，也未让旧泰拉人物可以套用任意地图。详情见 READINESS.md。上述条件完成前，状态保持draft，不以任意占位地图加“1-4”标题冒充正式关卡。
