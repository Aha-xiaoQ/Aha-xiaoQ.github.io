# 参与地图与关卡开发

先选择一个小范围：核对一段地形、实现一个机关、完善一个房间连接，或试用新增角色。大改动先在项目Issue中说明范围与原作依据。

建议流程：Fork仓库并新建分支 → 在data/campaign.json登记负责人/Issue → 基于底图fork独立草稿 → 修改并补测试 → npm run verify → 在M06独立副本接入 → 附试玩和差异证据提交PR。

不要把几何模板标为完成关卡，不把参考资料公开可见解释为资源已获授权。共用底图的修订需要保真依据；角色适配应进入自己的overlay或草稿，而不是覆盖基础地图。

提交资料至少包括：来源与许可、修改文件、影响关卡、已验证场景、未验证项、原底图变化说明。AI辅助代码仍需贡献者理解、核验和承担责任。发布由维护者审阅，不自动推送。

本地路径检查使用lstat，拒绝含悬空符号链接的路径；这不是对恶意并发修改父目录进程的安全沙箱。构建和更新时使用可信、未被其他进程改动的工作区。
