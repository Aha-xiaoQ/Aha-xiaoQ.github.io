# 参与地图与机制开发

先选择 `content/catalog.json` 中的关卡，确认角色方向与负责人，在对应 Issue 讨论认领。没有 Issue 或负责人时保持空白，提交 PR 后再填写实际链接。

一次提交聚焦一种改动：修正参考坐标、完成一个机制、加入一个角色方案，或补一组验收证据。不要把大批地形变化与物理修改混在一起。

参考坐标修改须附对照来源、区域、记录 ID、修改前后与截图。新增角色只在 `content/adaptations/` 添加配置；新的驱动能力先实现并测试，不能只添加能力名称。

执行 `npm run verify`。分区检查不能代替自然通关；水下、条件循环、升降台和结算需要各自验收。修改地图后运行 `npm run build` 并重新打包，网页状态与下载保持一致。

现有 M06 运行时属于配套基线，地图包不会把它重构成另一套游戏引擎。保留公开试玩，机制成熟后通过独立 PR 合并。
