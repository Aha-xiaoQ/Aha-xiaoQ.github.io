项目记录参与指南

YOUR FIRST CONTRIBUTION

先跑起来，再改一件事。

这是现有网站与三期游戏的协作准备版，不是重新实现的游戏，也不是联机模式。代码、画面、玩法和测试都可以贡献，但先看清自己的改动边界。

01 · 在仓库根目录启动

使用 Node.js 22 或更新版本。本轮协作工具没有第三方 npm 依赖，无需先执行 npm install。在已有完整仓库根目录运行：

npm run dev
# 浏览器访问 http://127.0.0.1:4173/dev/

Windows 也可双击根目录的 start-dev.cmd。终端保持打开，Ctrl+C 停止。端口占用时使用 npm run dev -- --port 4174。

下载的增量更新包不是完整游戏仓库。先按包内说明应用到原仓库；不要删除原目录。直接打开开发中心可以预览，但完整网站与三期游戏依赖原有文件。

02 · 从一个任务开始

在开发中心选一个任务，阅读验收标准和前置事项。卡片 ID（例如 DOC-001）不是 GitHub Issue 编号；打开表单并提交后才会创建实际 Issue。先确认无人重复认领，再 Fork、创建分支、提交小范围 PR。

阅读完整贡献指南。大规模重构、新角色、素材替换先讨论，不在一个 PR 中混合调手感、改地图和全仓格式化。

03 · 改状态，并让它真正共享

网页里的“编辑本地状态”只是当前浏览器的草稿。点击导出 project.json 后，将其放回仓库的 collab/project.json，核对修改日期、下次任务和交付状态，再运行：

npm run collab:build
npm run check
npm test
npm run doctor

提交状态源及两个生成文件：dev/project-data.js、collab/TASKS.md。标记任务完成必须填写验收依据；前置任务未完成时不会允许伪装为完成。

doctor 负责检查原游戏入口是否存在；它不会验证游戏能否通关。check 和自动测试主要覆盖协作工具，也不能代替手柄和音频实测。

04 · 每次中断，留下可恢复的记录

下一轮从 AGENTS.md、docs/collab/HANDOFF.md、任务状态和验证记录读取进度。用 npm run handoff 输出续接说明，或直接在开发中心复制。

先读取 GitHub 当前 main，再对照记录的 SHA 与本地版本。不能把旧聊天中的“最新版”当成事实。每轮只交付一份带文件清单、基线和回退说明的更新包，由维护者手动推送。

05 · 这几件事不要跳过

游戏代码与素材的许可审计仍在待办中。网站 MIT 不自动覆盖游戏、人物、音乐和音效；不得仅因为素材位于 GitHub 就认定可再分发。新增资源需要来源和授权依据，不清楚时使用已明确授权的占位素材。

本轮已准备 GitHub 模板与低权限检查文件，但分支保护、外部贡献工作流审批以及首次远端检查，仍需维护者按 设置清单 完成。文件存在不等于 GitHub 设置已经生效。
